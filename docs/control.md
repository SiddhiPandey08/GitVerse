# GitVerse Control & Governance

## 1. Stack and How to Run
- **Backend**: Express 5.2.1, Mongoose 9.7.3, Socket.io 4.8.3, aws-sdk 2.1693.0, Node ESM.
  - Run server: `cd backend && node index.js launch` (or `npm start`). Port: 3000 (`PORT`).
  - Env vars: `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET`, `MONGODB_URI`, `JWT_SECRET`, `CLIENT_ORIGIN`, `PORT`.
- **Frontend**: Vite 8.1.1, React 19.2.7, MUI 9.2.0, TailwindCSS 4.3.2, Socket.io-client 4.8.4.
  - Run web: `cd frontend && npm run dev`. Port: 5173.
  - Env vars: `VITE_API_URL` (defaults to `http://localhost:3000`).
- **CLI**: Executed via `node backend/index.js <command>`.
  - Env vars: `GITV_API_URL` (defaults to `http://127.0.0.1:3000`), `GITVERSE_EMAIL`, `GITVERSE_PASSWORD`.

## 2. Invariants That Must Never Break
1. **Commits are append-only**: History is never rewritten. Commits are inserted monotonically (`backend/controllers/repoControllers.js` `updateRepository`, `backend/models/commitModel.js`).
2. **Current files = latest key per file name**: Derived by mapping oldest-to-newest commit file keys (`frontend/src/components/repo/RepoFiles.jsx` `currentFiles`).
3. **S3 key format**: Always `${repoId}/${commitId}/${name}` (`backend/controllers/repoControllers.js` `getUploadUrls`, `backend/controllers/push.js`).
4. **Revert reuses keys and never rewrites history**: Creates a new forward commit reusing earlier S3 keys without copying storage objects (`backend/controllers/repoControllers.js` `revertCommit`).
5. **Commit author is set server-side from JWT**: `req.user._id` is stamped directly; client input for author is ignored (`backend/controllers/repoControllers.js` `updateRepository`).
6. **getRepoAccess is the single source of truth**: Centralized authorization for private/public visibility and roles (`backend/utils/repoAccess.js`).
7. **Guests cannot join calls or channels**: Unauthenticated sockets are denied access to channels and call rooms (`backend/sockets/meeting.js` `canJoin`, `backend/sockets/channels.js`).
8. **Display names come from socket.user, never client payload**: Identity is stamped strictly from verified token (`backend/sockets/meeting.js`, `backend/sockets/channels.js`).
9. **Chat is saved before broadcast**: Messages are persisted to MongoDB prior to emitting to socket rooms (`backend/sockets/channels.js`).
10. **Channel socket events are prefixed "channel:"**: Namespacing prevents collision with signaling (`backend/sockets/channels.js` `channel:join`, `channel:leave`, `channel:message`).
11. **CLI never holds AWS credentials**: S3 credentials reside only in server env. CLI interacts via signed URLs using plain Axios (`backend/controllers/push.js`, `backend/controllers/pull.js`).
12. **CORS origins from env**: Parsed from `CLIENT_ORIGIN` env var (`backend/server.js`).
13. **.env is never committed**: Listed in `.gitignore` for both backend and frontend (`.gitignore`).

## 3. Decision Log
- **Meridian merged into GitVerse under `features/meeting/`**: Avoids separate server infrastructure and unifies JWT authentication.
- **Roles (owner / collaborator / viewer) and no pull requests**: Provides a simple, branchless append-only collaboration model without git merge overhead.
- **Collaboration requests via issues**: Re-uses the issue tracker with `requestCollaboration: true` instead of building separate access request workflows.
- **Revert instead of rebase**: Preserves immutable commit logs and linear history by recording changes as new revert commits.
- **Voluntary `--review` flag**: Lightweight review signal that notifies teammates in `#general` without blocking pushes.
- **Signed S3 URLs**: Keeps cloud storage credentials isolated to the backend and offloads file transfer directly to object storage.

## 4. Conventions
- **Comments**: 2-3 line file header comment + plain-English comment above every function explaining what, why, and non-obvious steps. No line-by-line noise.
- **Naming**: camelCase for functions/routes, PascalCase for models and React components, kebab-case for socket rooms and channel names.
- **Adding features**: Follow flow: Mongoose model -> Controller -> Express Route -> Socket handler (if live) -> Frontend API/Component.
- **Don'ts**:
  - Never test CLI commands inside the project root (always use a throwaway temp directory outside).
  - Never duplicate access logic outside `backend/utils/repoAccess.js`.
  - Never import `aws-sdk` into CLI controllers.

## 5. Known Gaps / TODO List
- **Production CORS / proxy**: `CLIENT_ORIGIN` defaults to localhost; production environments must configure explicit origins.
- **`meridian-import/` cleanup**: Legacy standalone video meeting folder is unreferenced and can be safely removed.
- **Call screen restyling**: Video conference component uses ad-hoc inline styles and requires theme alignment.
